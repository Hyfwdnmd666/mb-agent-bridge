# 结构化状态 + 命名动作：让 Agent 真正能玩

> **2026-09-30 更新**：观察端（A）已经打通，而且**不需要碰运行中的游戏**——直接读存档。
> 见 `tools/save_state.py`。只剩动作端（B）还需要一条通道。

## 0. 已破开的存档格式（实测数据）

存档位置：`Documents\Mount&Blade Savegames\<模块名>\sg00.sav`（约 2.3 MB）

```
+0x00  'WRDR'                 魔数
+0x04  uint32 0x3F3           1011 —— 游戏版本号，自证
+0x0C  uint32 len + bytes     玩家名（长度前缀字符串，明文）
```

### 队伍记录（定长数组，步长 4392 = 0x1128）

以 0x4E230 这个已知队伍为例，记录内部布局：

```
+0x00   float x        ┐
+0x04   float y        │ 坐标连存三份（x,y,x,y,x,y），
+0x08   float x        │ 这个冗余正是识别队伍记录的依据
+0x0C   float y        │
+0x10   float x        │
+0x14   float y        ┘
+0x18   float  朝向/旋转
+0x1C   int    16
+0x20   int 兵种ID ┐
+0x24   int 人数   ┘  其后每 16 字节一组 (兵种ID, 人数, 0, 0)
+0x30   int 兵种ID ┐
+0x34   int 人数   ┘
   ... 重复
```

**所以存档里不但有坐标，还有每个队伍的完整兵力构成。**

### 识别方法（为什么能过滤掉噪声）

原始扫描会找出约 750 个落在 ±105 范围内的 float 对，但只有 57 个构成
**"间隔 8 字节、连续三个以上"** 的簇。`(1.0, 1.0)` 出现 25 次、
`(10.0, 1.0)` 出现 91 次，那些是缩放/旋转默认值，按出现次数和已知默认值过滤。

### 尚未定位

- **金钱**：活的进程里读得到（`block + 0x3D8`），但存档里搜 `5271` 零命中
  —— 存档是较早的快照，金钱已经变了。需要用"改金钱前后各存一次档再差分"来定位。
- **日期/时刻**：`第24天 4:43` 在存档里也没找到直接的 int 24/4/43 组合。
  同样建议用差分法。

## 0.1 原始设计（以下仍适用，但观察端的实现路径已变）

> 这份文档是 A+B 层的设计。核心论点：**Agent 玩不好骑砍，不是模型不够聪明，是接口太原始。**
> 它现在靠像素猜、靠坐标点。把观察端和动作端都换成文字，能力立刻上一个量级，不用训练模型。

## 2. 目标形态

### A. 结构化状态（观察端）

不给截图，给文字：

```
位置:(44.4, 6.7)  金钱:5271  第24天  时刻:4:43
队伍:23人  士气:78  当前:城镇-萨哥斯
可见: 强盗x2(距3.2) 商队x1(距5.8)
```

### B. 命名动作（动作端）

不给坐标，给指令：

```
travel_to 萨哥斯
enter_town
talk_to 杰姆斯
buy 面包 x20
```

### 为什么这能绕开鼠标

**动作由游戏自己执行**——通过引擎的脚本 API（`party_set_position`、`party_set_ai_target_position` 等），
**完全不经过 Windows 输入栈**。DirectInput 那套区分注入的逻辑在这里不存在。

## 3. 传输层：共享内存

模块脚本不能读写文件，也没有网络。所以信箱放在**引擎的全局变量数组**里。

### 已经验证过的事实

| 事实 | 证据 |
|---|---|
| 全局变量块可用 AOB 签名稳定定位 | 24 字节签名，跨重启可复现 |
| 变量 N 在 `block + N*4` | `block+0x3D8` = 金钱，与 HUD 一致（5271） |
| 模块 `.txt` 文件是纯文本、可手写 | `simple_triggers.txt` 格式已解 |
| 原版 1.011 有坐标 API | `menus.txt` 里明文出现 `1625`/`1626` |
| **追加变量索引不可行** | 数组在索引 ~248 附近结束，499+ 落在别的结构上 ✗ |

**最后一条是关键约束**：不能新增变量，只能用**已存在的、当前没被使用的**槽位。

### 安全的槽位选择

`variables.txt` 里 499 个变量全部被模块代码引用过——但"被引用"不等于"运行时有意义"。
**任务专用变量在该任务未激活时是死槽**：

| 索引 | 变量名 | 何时安全 |
|---|---|---|
| 480–486 | `g_custom_battle_*`、`g_notification_menu_var*`、`g_cur_week_*` | 非自定义战斗时 |
| 487–490 | `g_presentation_marshall_selection_*`、`g_center_to_give_to_player`、`g_random_army_quest` | 元帅选举界面未开时 |
| 491–493 | `qst_scout_waypoints_wp_1..3` | 无侦察任务时 |
| 494–496 | `qst_scout_waypoints_wp_*_visited` | 同上 |
| 497–498 | `qst_train_peasants_*`、`g_village_raid_evil` | 无对应任务时 |

**首选 491–498 作为命令信箱**（8 个槽），**480–486 作为状态回读**（先确认没有活跃任务占用）。

> 更稳的方案是让玩家先确认没有活跃任务，或者改用 **party slot**（队伍槽位是另一个数组，
> 大概率有空闲高位）——这条待验证。

## 4. 脚本层：两个 simple_trigger

`Modules/<mod>/simple_triggers.txt` 是纯文本。格式：

```
simple_triggers_file version 1
<N>                                    ← 触发器条数，改文件必须同步改这里
<周期秒>  <顶层语句数>  <opcode> <参数数> <参数...> ...
```

**周期 0.0 = 每帧**。语句是前缀式：`<opcode> <num_args> <args...>`。

### 编码表（已核对）

| 名称 | 编码 |
|---|---|
| 玩家队伍 | `648518346341351424` |
| pos0 / posN | `72057594037927936` + N |
| 全局变量 N | `144115188075855872` + N |
| 寄存器 N | `1224979098644774912` + N |

| 操作 | opcode | 参数 |
|---|---|---|
| `party_get_position` | 1625 | (pos, party) |
| `party_set_position` | 1626 | (party, pos) |
| `party_set_ai_target_position` | 1642 | (party, pos) |
| `position_get_x/y` | 726 / 727 | (dest_fixed_point, pos) |
| `position_set_x/y` | 729 / 730 | (pos, value_fixed_point) |
| `assign` | 2133 | (dest, value) |
| `val_add` | 2105 | (dest, value) |
| `party_get_num_companions` | 1601 | (dest, party) |
| `eq` / `try_begin` / `try_end` | 31 / 4 / 3 | — |
| `display_message` | 1106 | (string_id) |

### 触发器 1：状态回读（每帧）

```
0.000000 8
1625 2 72057594037927936 648518346341351424      party_get_position(pos0, player)
726 2 1224979098644774912 72057594037927936      position_get_x(reg0, pos0)
727 2 1224979098644774913 72057594037927936      position_get_y(reg1, pos0)
2133 2 <gv480> 1224979098644774912               gv480 = x  (定点数, 米×100)
2133 2 <gv481> 1224979098644774913               gv481 = y
1601 2 1224979098644774914 648518346341351424    party_get_num_companions(reg2, player)
2133 2 <gv482> 1224979098644774914               gv482 = 兵力
2105 2 <gv483> 1                                 gv483++   (心跳，用于确认触发器在跑)
```

### 触发器 2：执行命令（每帧，有命令才动）

```
0.000000 6
31 2 <gv491> 1                                   eq(gv491, 1)  → 有命令
4 0                                              try_begin
2133 2 72057594037927937 <gv492>                 pos1 = gv492   (目标 x)
2133 2 72057594037927938 <gv493>                 pos1 = gv493   (目标 y)
1626 2 648518346341351424 72057594037927937      party_set_position(player, pos1)
2133 2 <gv491> 0                                 清命令
3 0                                              try_end
```

> **待验证**：`2133 2 posN <int>` 是否真能给位置寄存器赋值。`conversation.txt` 里有
> `2133 2 1224979098644774912 72057594037927936`（reg＝pos）的用法，方向相反，需要实测。
> 备选写法：`729 2 pos1 <x>` / `730 2 pos1 <y>`（`menus.txt` 里大量出现，**原版确认存在**）。

## 6. 与现有桥的关系

这套 A+B **不替代** `mb_bridge.py`，而是补上它的两端：

```
mb_bridge.py      截图（兜底观察）、金钱（已可用）、邮箱读写
   +
模块触发器        结构化状态（A）+ 命名动作（B），不碰输入栈
   =
完整的 agent 循环：文字状态进 → 决策 → 命名动作出
```

反射层（`fight`）保留，负责实时战斗——那一层永远不该由模型驱动。

## 7. 已知坑（今晚踩过的，别再踩）

1. **别追加全局变量索引** —— 数组在 ~248 就结束了，499+ 是别的结构。
2. **窗口必须完全在任务栏之上** —— 否则点击落在任务栏，而且截图看不出（BitBlt 抓的是窗口自身内容，不受遮挡影响）。
3. **游戏失焦会自动暂停**，配置里没有开关。
4. **空格是大地图的暂停键** —— 想"推进对话"按空格会把游戏暂停掉。
5. **`SendInput` 发给前台窗口** —— 调用前必须先把游戏提到前台。
6. **改模块文件后必须重启游戏** —— 引擎只在启动时读。
7. **改 `simple_triggers.txt` 必须同步改第二行的条数**，否则解析错位。
